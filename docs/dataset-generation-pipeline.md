# Dataset Generation Pipeline: Neuro-Symbolic Sanskrit AI

This document outlines the end-to-end dataset creation pipeline for the Panini Neuro-Symbolic AI architecture (`pretrain-S-PA` Tiny Transformer + RLCD + `Vidyut` Engine). 

Because the neural model acts as a semantic intent parser mapping English to Paninian Abstract Syntax Trees (AST), the training dataset requires rigorous alignment between English sentences and valid Paninian schemas.

> **Status:** Draft design, not adopted; nothing here has been built. Reviewed
> in `docs/RLCD_TRANSITION_PLAN.md` (draft amendment 0.7), section 3. Under
> that plan, dataset work starts on the Sanskrit side (stage 3): a small,
> reviewed Tier 1 generator and DCS morphology. English pairs come in stage 4.
> Three corrections apply throughout:
>
> 1. **Vidyut does not reject invalid ASTs.** It derives forms from invented
>    roots, the wrong gaṇa and impossible voice–number combinations. Every
>    "Vidyut check" below means a constraint layer *plus* Vidyut: Dhātupāṭha
>    lookup, pada, transitivity, voice and number limits, stem gender from the
>    kosha, and a round trip from the derived form back to the AST.
> 2. **A passing check proves form, not meaning.** It cannot tell whether the
>    AST matches the English sentence. Label noise in LLM-produced pairs must
>    be measured on a human-checked sample.
> 3. **Generated Sanskrit is synthetic, never attested,** even when a human
>    translates the English (protocol section 8.4).

## 1. Dataset Taxonomy

To train the RLCD decision heads and benchmark the model reliably, the data is partitioned into four distinct categories:

### A. Gold Dataset (High-Fidelity / Ground Truth)
* **Definition:** Data pairs whose labels an expert has verified. Pairs whose Sanskrit side was generated (Tier 1) stay labelled synthetic even after expert review of the English.
* **Volume Target:** Sized to reviewer time. Two expert reviewers are available; the first gold set follows `docs/GOLD_SET_PLAN.md` (a few hundred items). Tens of thousands of gold pairs would need many more reviewers.
* **Purpose:** Fine-tuning the RLCD heads for ultimate accuracy and evaluating the test sets.

### B. Silver Dataset (Compiler-Verified Synthetic)
* **Definition:** High-volume synthetic data where the English translation or the Paninian AST was generated by an LLM, and the AST passes the constraint layer and Vidyut derivation (see the status note). Pairs that fail are discarded. Passing does not show that the AST matches the English. Check each LLM's terms on using its outputs to train models before use.
* **Volume Target:** 1M+ pairs.
* **Purpose:** Pretraining the RLCD representations and exposing the neural model to massive structural diversity (all *gaṇas*, rare *lakāras*, complex *kārakas*).

### C. Dev Dataset (Validation)
* **Definition:** A stratified random sample of 2,000 - 5,000 pairs held out from both Gold and Silver sets.
* **Purpose:** Hyperparameter tuning (e.g., finding the optimal temperature $T$ for the RLCD calibration head) and calculating the Expected Calibration Error (ECE) at the end of each epoch.

### D. Test Dataset (Hold-Out Benchmark)
* **Definition:** A strictly Gold-tier dataset (human-verified, classically sourced), entirely unseen during training, its size set by reviewer time (see Gold above). It must also exclude every text in the pretraining corpora and the held-out chapter manifest of `docs/GOLD_SET_PLAN.md`.
* **Purpose:** Final reporting for arXiv submissions. It should contain an adversarial subset (e.g., sentences with complex *Sandhi* ambiguity or rare passive voice alignments) to prove the RLCD confidence gate correctly routes uncertainty to the symbolic fallback.

## 2. Sourcing Strategies & Generation Instructions

### Tier 1: Reverse Synthetic Generation (The Engine-First Approach)
**Target:** Yields Silver data, labelled synthetic. Start small (about 30 roots, 300 stems, 10,000 sentences) and review a sample before scaling.
**Concept:** Generate provably correct Paninian ASTs first, then translate them to English.

1. **AST Sampling:** Write a Python script to sample valid combinations of Paninian parameters.
   * *Dhātu* (Root): Sample from the 2,000+ roots in the *Dhātupāṭha*.
   * *Lakāra* (Tense/Mood): Sample across `laṭ`, `liṭ`, `luṭ`, `lṛṭ`, `loṭ`, `laṅ`, `vidhiliṅ`, `āśīrliṅ`, `luṅ`, `lṛṅ`.
   * *Kāraka*: Assign valid nominal stems (*prātipadika*) to agent/object slots, with selectional constraints (for example an animate agent for *pā*). Uniform sampling produces grammatical nonsense.
   * Write roots as their Dhātupāṭha entries in SLP1 (`ga\mx~`, not `gam` or `gam\l~`) and check them against `dhatupatha.tsv`.
2. **Vidyut Compilation:** Pass the AST through the constraint layer, then to `vidyut-prakriya` and `vidyut-sandhi`. The Rust engine deterministically derives the Sanskrit string (e.g., `bAlako gfhM gacCati`), valid for the encoded rules.
3. **Template Mapping & Distillation:** 
   * Pass the structured intent to a local LLM (Mistral/Llama-3) with a prompt: *"Given this grammatical intent (Subject: Boy, Object: Home, Verb: Go, Tense: Present), generate 5 diverse English translations."*
   * *Outputs:* "The boy goes home", "A young boy is walking to the house", etc.
4. **Save Pair:** `(English Text, AST)`, following `docs/architecture/rlcd_decision_schema_specification.md`. All paraphrases of one AST share a group ID and stay in one split. Hold out roots and stems lexically.

### Tier 2: Mining Existing Aligned Corpora (The Empirical Approach)
**Target:** Yields **proposals**, not gold. Corpus labels and automatic analyses become gold only after expert review. Licences for each source must be checked first (Mitrasaṃgraha, Itihasa and BPCC are not yet checked; DCS is CC BY 4.0).
**Sources:**
* **Mitrasaṃgraha:** 391,000+ aligned Sanskrit-to-English pairs.
* **Digital Corpus of Sanskrit (DCS):** 5.6 million morphologically tagged records (lemmatized roots, case endings, compounds).
* **AI4Bharat BPCC & Itihasa:** 270k+ parallel pairs covering the epics and classical literature.

**Extraction Pipeline:**
1. Isolate the Sanskrit sentence from the parallel bitext.
2. Run the Sanskrit string through `vidyut-cheda` (segmentation) and `vidyut-kosha` (morphological parsing). Both return several analyses for many words; keep the ambiguity rather than picking one silently.
3. Map the morphological tags back into your `RLCD_DECISION_SCHEMA`.
   * *Example:* If DCS tags a word as `[Root: gam, Class: 1, Voice: Active, Tense: Imperfect, Num: Plural]`, map it to `{"dhatu": "ga\\mx~", "prayoga": "kartari", "lakara": "laN", "vacana": "bahuvacana"}`.
   * DCS tags case, not kāraka, and case does not map one-to-one onto role: *tṛtīyā* can be the agent of a passive, an instrument, or the companion after *saha*. Use *vibhakti* as the first target; add kāraka only with a reviewed case-to-role mapping.
4. Pair this extracted AST with the human English translation provided in the corpus. Classical translations are free and often not sentence-aligned, so check alignment on a sample.
5. Run the same leakage audit as the pretraining corpora: DCS-derived text overlaps P-A, P-B, the right-word holdout and the gold-set held-out chapters.

### Tier 3: Direct LLM Schema Distillation (Modern English Adaption)
**Target:** Yields Silver data optimized for modern, conversational English.
**Sources:** Conversational English datasets like **OpenOrca** or **UltraChat**. Both contain model outputs; check their licences and the terms of the models that produced them before use.

**Execution:**
1. Sample conversational English (e.g., *"Can you tell me where the library is?"*).
2. Prompt an LLM whose terms allow it to map the English sentence into the AST format of `docs/architecture/rlcd_decision_schema_specification.md`.
3. **The Compiler Check (Crucial Step):** Pass the LLM's JSON into the Vidyut Paninian compiler.
   * Vidyut alone does not throw errors for an invented *Dhātu* or an illegal pada; the constraint layer must catch them. If either rejects the AST, **discard the pair entirely**.
   * If both accept it, save the pair to the Silver dataset. This removes ill-formed ASTs, not wrong ones: a valid AST for the wrong meaning still passes. Estimate that rate on a human-checked sample before training on Tier 3 data.

## 3. Implementation Steps for GitHub Repo

Create a `data_pipeline/` directory in your repository with the following structure:

```text
panini-neuro-symbolic-ai/
├── data_pipeline/
│   ├── 01_reverse_generation.py     # Generates Tier 1 synthetic ASTs
│   ├── 02_mine_corpora.py           # Parses Mitrasaṃgraha/BPCC into RLCD JSON
│   ├── 03_llm_distillation.py       # Calls LLM APIs and filters via Vidyut check
│   ├── 04_stratify_splits.py        # Shuffles and outputs Gold/Silver/Dev/Test
│   └── schemas/
│       └── rlcd_dataset_schema.json # JSON-Schema for strict data validation
```

### Build Instructions

1. **Initialize Corpora:** after checking their licences, download Mitrasaṃgraha and AI4Bharat Itihasa into a local `data/raw/` folder, and record source URLs and hashes.
2. **Generate Silver Base:** run `01_reverse_generation.py` on a small, reviewed root and stem inventory first (about 10,000 sentences); scale only after a reviewed sample is acceptable.
3. **Extract Classical Proposals:** run `02_mine_corpora.py`. Vidyut returns no confidence score, so filter on analysis ambiguity instead: keep sentences where every word has a single analysis consistent with the corpus tags, and flag the rest for review.
4. **Compile Splits:** run `04_stratify_splits.py` to write `train_silver.jsonl`, `train_gold.jsonl`, `dev.jsonl` and `test.jsonl`, grouping paraphrases of one AST and holding out roots and stems.

Each line of the final `.jsonl` files follows `docs/dataset-structure.json`.
